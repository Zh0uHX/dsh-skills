# 异常退出后恢复

普通网络或文件写入错误会回滚。进程被强制终止或断电可能留下空锁和暂存目录；插件不会自动猜测哪份文件应生效。

先停止使用该技能目录的所有 DSH 进程，再备份整个技能目录，包括隐藏文件。关闭浏览器不等于停止 DSH。以下操作只针对设置页显示的技能根目录；遇到符号链接、损坏记录或无法确定的候选版本时保留现场。

| 位置 | 内容 |
| --- | --- |
| `.dsh-skills/state.json` | 最近一次提交的安装记录 |
| `.dsh-skills/lock` | 正常为空的互斥锁目录 |
| `.dsh-skills/stage-*` | 未完成安装或回滚的文件 |
| `.dsh-skills/backup-*`、`removed-*` | 更新或卸载前的文件，可能包含本地修改 |
| `skill-*/.dsh-skills-managed.json` | 活动目录的所有权标记 |

恢复时核对记录、目录和所有权标记中的技能 ID。记录的 `contentHash` 是所有技能文件按相对路径排序后，`[{path, contents}]` 的 JSON UTF-8 字节的 SHA-256；不包含所有权标记。记录和活动目录的内容一致时，先归档残留的暂存/备份目录，再用 `rmdir` 删除精确的空锁目录。不要递归强制删除 `.dsh-skills`。

活动目录缺失时，可核验同一 ID 的备份后恢复到原路径；如果不再需要原内容，先保留备份，清理空锁、重启 DSH，再对“目录已不存在”的记录确认卸载，这只会清理元数据。随后可以重新安装。

活动目录与记录不一致、候选版本不唯一或记录损坏时，需要人工选择一致的备份。目录切换和记录提交不是一个断电事务，不能凭修改时间自动判断。不要用 `state-*.tmp` 直接覆盖正式记录，也不要伪造所有权标记。

恢复后先查看列表，再检查更新。发现本地修改时，确认更新会覆盖它们。
